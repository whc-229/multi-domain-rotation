# 排班：全新机队同时上线的"启动代价"与提前大修错峰（2026-10-26）

背景：老师暂时见不到，用户让我按研究空白自己选方向探索，要求"论文能出成果"。本文是这一轮的调研、选题、试点结果和论文方案。所有数字都是本轮实测。

## 0. 结论先行

1. **选题**：全新机队同一天上线时，所有机器人维修节拍完全同步，第一轮大修会扎堆，必须多买机器人扛过去。这部分"启动代价"在稳态分析里看不到。用"提前大修"主动错峰可以把它消掉一大半。进化算法负责学派工规则，线性规划给出错峰计划。
2. **启动代价很大**：6 种真实机型单站时，全新上线比稳态多需要 13%–27% 的机器人（流体值）；允许提前大修后降到 1%–13%。整数精确解例子：L1-1 型 3 个岗位，稳态 25 台、全新上线 29 台、允许提前大修 27 台。
3. **以前"下界太松"的原因找到了**：带工具的单站实例 L1/L2/L3，稳态下界是 10/9/10，全新启动下界是 13/11/12，正好等于已知最优。多站实例上，进化解对新下界的差距从原来的 25%–33% 缩小到 5%–16%。
4. **方法在单型上很强，在多站上显著但幅度小**：
   - 单型多岗位：用"LP 计划的提前大修 + 进化派工"，L1 系列 9 个实例全部达到"允许提前大修"时的精确最优，比不提前大修的进化解少 1–4 台（5%–12%）；L3 系列少 1–5 台，已知精确值的两个实例各差 1 台。
   - 多站带工具（2–4 站，36 组配对）：LP 引导派工 + LP 提前大修计划，比不提前大修的进化派工平均少 0.58 个资源（p = 0.009），最多少 3 个。只差"提前大修计划"这一项的干净对照：平均少 0.67 个（22 组更少、12 组相同、2 组更多，p < 0.001）。所有解在 60 万格内无缺岗，39/40 被严格证明永远可行。提前大修只在启动期发生 3–47 次，进入周期后为 0，长期维修量不变。
   - 但不是每个实例都受益：LP 显示没有错峰空间的 3 站 s4，以及 4 站 s4，反而多 1 个；6 站只跑完 s1（平均少 1 个）和 s2 的 1 个种子（多 3 个）。
   - 对照：让进化算法自己学"何时提前大修"的线性规则无效（36 组平均 −0.14，p = 0.50）；按编号机械错峰更差；只加计划、不配合 LP 的机型配比和派工引导，不稳定（4 站 s3 多 2–13 个）。错峰的时机和机队配比都要由 LP 给出。

## 2. 现象：为什么全新上线要多买

- 每台机器人的维修是循环的，比如每值 3 个短班后做 1 次大修。稳态时，机队里的机器人处在循环的不同位置，大修错开，所需台数接近流体下界。
- 全新机队同一天上线，所有机器人都在循环起点，会在差不多同一时间进入第一次大修。这段时间必须有额外的机器人顶班。机队规模是一次买定的，所以要按这个峰值买。
- 第三轮的理论已经证明：这部分额外台数一般**随岗位数线性增长**，不是常数（定理 8）；允许提前大修，很多序列的线性部分会消失（第 4 节机证表）。
- **最优部署长什么样**（精确整数解，L1-1 型 3 个岗位）：
  - 不许提前大修：29 台，前 120 格的派工一直不规则。
  - 允许提前大修：27 台，只做了 9 次提前大修，分 3 批，每批 3 台：第 14 格上岗的一批值完第 1 班就去大修，第 26 格上岗的一批值完第 2 班就去，第 38 格上岗的一批值完第 3 班就去。从第 41 格起，派工变成严格的相位 0、1、2、3 轮转，之后再也不提前大修。
  - 也就是说，最优做法是在启动期把机队"拆成几批、错开第一次大修"，然后进入完全均匀的稳态。

## 4. 方法与对照（C++ `rost4`，同一套仿真、定台数、循环证书）

每个配置都在 2–4 站 12 个实例 × 3 个进化种子上跑，(4+12)-ES，10 代。所有配对比较都在同一实例、同一种子上做（Wilcoxon 符号秩检验）。

| 配置 | 做法 | 对照 | 结果 |
|---|---|---|---|
| 不提前大修（curdef；pad 为同随机数流的对照） | 进化派工；相位特征改成"当前各相位人数"，否则提前大修会让状态无限增长、无法判环 | — | 基准 |
| 学出来的提前大修规则（reset） | 进化算法同时学一个线性打分：本相位拥挤度、相位 0 拥挤度、相位位置、时间 | 对 pad，36 组 | 平均 −0.14，p = 0.50，**无效** |
| 按编号错峰（stagger） | 每型第 c 台在首个超周期第 (c mod L)+1 班后提前大修 | 单型 3 个实例 | 多 3–4 台，**更差** |
| 只给次数不给时机（quota） | 各相位提前大修次数取自精确解，第一次有机会就做 | 单型 L1-1 × 3 | 30 台，与不提前大修相同，**无效** |
| 给次数也给时机 | 同上，但只在精确解里的时刻之后才做 | 单型 L1-1 × 3 | 27 台 = 精确最优 |
| 只加 LP 计划（planf） | 解"允许提前大修"的全新启动 LP，读出各型、各相位、各时刻的提前大修流量，按实际台数换算成整数计划 | 对 curdef，35 组 | 平均 −0.31，p = 0.066；4 站 s3 上多 2–13 个，**不稳定** |
| 只加 LP 引导派工（lpgc） | 派工打分加入"LP 解里该型承担该站的比例"，定台数从 LP 台数出发 | 对 curdef，36 组 | 平均 +0.08，p = 0.55，**无效** |
| **LP 引导派工 + LP 计划（lpgplan）** | 两者合用 | 对 curdef，36 组 | 平均 **−0.58**（少 17、同 11、多 8），p = 0.009，最多少 3 个 |
| | | 对 lpgc（只差计划），36 组 | 平均 **−0.67**（少 22、同 12、多 2），p < 0.001 |

- 单型多岗位上（第 3.2 节），只加 LP 计划就足够：机型只有一种，不存在配比问题。
- 多站带工具时，计划要和 LP 的机型配比、站点分工一起用才稳定。LP 引导派工本身不省资源，它的作用是让计划"对得上号"。
- 解的质量：lpgplan 的 40 次运行全部在 60 万格内无缺岗，39 次被严格证明永远可行；提前大修 3–47 次，全部发生在启动期。
- 用时：每次进化平均 83 秒（2–4 站）；LP 每个实例 0.3–14 分钟（6 站最慢）。
- 不受益的实例：3 站 s4、2 站 s2 的 LP 显示没有错峰空间（两个下界相同），用了反而略差；4 站 s4 有 1 个资源的空间，但也多了 1 个。6 站 s2 的 1 个种子多 3 个。按 LP 显示的空间决定是否启用，可能是一条实用规则，但这是事后观察，还没验证。

## 5. 论文方案与创新点评估

**暂定题目**：《提前维修换更少机器人：多型号多站点永久排班中全新机队的错峰部署》

**主线**：现象（启动代价） → 界（全新启动 LP 下界） → 手段（提前大修错峰） → 方法（LP 计划 + 进化派工 + 循环证书） → 证据（单型精确、多站统计）。

| 创新点 | 证据 | 能否立住 |
|---|---|---|
| 量化全新上线的启动代价：随岗位数线性增长，真实机型 13%–27% | 第三轮定理 8、本轮流体表和精确表 | 能。相关文献只做了经验观察和"多配备用机" |
| 全新启动时间展开下界：单站等于已知最优，多站解释了旧下界一半的缺口，8 站十几分钟 | 3.3 节；2 站两个实例用完全整数规划复核未变松 | 能，方法简单但结论有用 |
| 提前大修作为错峰手段，给出最优部署结构（分批错开第一次大修，然后均匀轮转） | 精确解结构、机证表 | 能，反直觉而且实用 |
| LP 计划 + 进化派工的混合方法 | 单型 L1 系列达到精确最优；多站 2–4 站显著但幅度小（平均 −0.58，最多 −3），个别实例变差，6 站证据不足 | 中档期刊可以；要更强，需要把多站上剩下 10%–16% 的差距压下去，并补 6–10 站 |
| 循环证书保证永久可行 | 全部解严格证明 | 作为组件，不单独当卖点 |

适合的期刊方向：自动化与机器人调度类（如 IEEE T-ASE）、运筹应用类（如 Computers & Operations Research）、进化计算应用类（如 Swarm and Evolutionary Computation、Applied Soft Computing）。这和老师的"超长排班"一致：很长但有限的时域，本质上就是"启动期 + 稳态"，本文正好把两段接起来。

**风险**
- 多站带工具时，提前大修本身能省的空间只有 0–3 个资源，主要差距在派工；方法部分的说服力要靠更大的实例和更好的派工。
- 方法不是对每个实例都有利（3 站 s4、4 站 s4 多 1 个，6 站 s2 的一个种子多 3 个），需要一条"何时启用"的规则。
- L3 系列和多站的精确值还不全，"接近最优"只能对 L1 系列和单站说。
- 实例是随机生成的，机型参数来自真实数据。
