# 启发式算法在超长/无限期排班上的作用验证（2026-10-14）

模型：`slotmodel.py` 的班次槽模型（由 `roster_sim.py` 的维修规则算出每台机器人的槽间隔序列；只考虑机器人，工具可单独按下界配齐）。
K = 值班点个数（每槽需要 K 台不同机器人）。所有"成功"都是**无限期可行证书**（前缀 + 可无限重复的周期，经逐槽复核），
只有"全时域 GA"是有限时域 H 内可行，不是证书。

## 比较的方法

| 方法 | 文件 | 编码 / 思路 | 编码长度 |
|---|---|---|---|
| 全时域随机键 GA（基线，同现有 MOEA 的编码思想） | `kpost.fullkey` | 每槽一个基因 | H×K，随时域增长 |
| 精确 DFS 找环 | `kpost.exact` | 有限状态图上找可达环，同型机器人合并状态 | 无编码；节点上限 30 万 |
| JSP 式循环编码 + 冲突局部搜索 + 前缀搜索 | `kpost.cyclic` / `prefix` | 周期 = 带重复的机器人编号序列（机器人≈工件，每一班≈工序），POX 交叉、JIT 播种、只移动违约班次；再用束搜索/深搜从全新状态进入该周期 | 周期长度 P×K，与 H 无关 |
| 策略编码 GA | `policy.py` | 只编码"派谁"的 5 个打分权重，确定性仿真到状态重复 | 5 |
| 状态类别 ACO | `algos.aco` | 信息素挂在 (组, 相位) 上的逐槽构造 | — |
| **结构分解** | `decomp.py` | K 个点 → 机器人分 K 组、每组专守一点；外层分组（速率 LPT + 组间交换局部搜索），内层单点精确找环 | 分组方案 |

## 结果

### A. 同型、单值班点（你现有的实例）：编码随时域变长，基线就失效（`expA.json`）

| 实例 | 精确找环 | 全时域 GA 成功率 H=144 / 720 / 2880 槽 | 循环编码+前缀 |
|---|---|---|---|
| L1 0型 7台 | 15 个节点 | 5/5, 5/5, 1/5 | 5/5 |
| L2 0型 5台 | 16 | 5/5, 5/5, 5/5 | 5/5 |
| L3 0型 6台 | 1759 | 5/5, **0/5, 0/5** | 2/5（失败都卡在前缀） |
| L1 2型 8台 | 61 | 5/5, 5/5, 5/5 | 2/5 |
| L1 2型 7台（不可行） | 证明不可行 | 0 | 0 |

### B. 异构机器人（各级维修参数 ±30% 扰动）、K 个值班点：最少机器人数（`expB.log`、`decomp.log`）

| K | 池 | 速率下界 | 精确（30 万节点内） | 全时域 GA（仅有限 144 槽） | 循环编码+前缀 | **结构分解** |
|---|---|---|---|---|---|---|
| 1 | 0/1/2 | 5/6/6 | 6/6/7 | 6/6/7 | 6/7/7 | 6/6/7 |
| 2 | 0/1/2 | 11/11/11 | 15/14/15 | 12/12/13 | 无 | **12/12/12** |
| 3 | 0/1/2 | 16/16/17 | 无（≤下界+4 都未决） | 18/17/19 | 无 | **18/18/（未跑完）** |

- 全时域 GA 在 K=2、N=12 上：H=144 槽 3/3 成功，H=720 与 1440 槽 0/3 —— 和 A 一样随时域失效。
- 策略编码只在简单实例上成功（L1/L2），L3 和异构多点都失败；状态类别 ACO 在 L3 上也失败。

## 结论

1. 同型、单点：精确找环最快（≤1759 节点），启发式没有必要。
2. 全时域编码的失败是"随 H 变长"导致的，而不是解码器或模型的问题。
3. 规模一大（多值班点 + 异构参数），精确方法在节点上限内证不出任何解，**结构分解（外层启发式分组 + 内层精确）**
   在 K=2 上把资源数从 14–15 降到 12（下界 11），K=3 上给出 18（下界 16–17），且都有无限期证书。
4. 直接在周期表上做进化（循环编码）和策略编码都不够好：前者的难点在"从全新状态进入周期"（前缀），后者表达能力不足。

## 复现

```
python exp.py A      # 实验 A
python exp.py B      # 实验 B（精确 / 循环编码 / 全时域）
python decomp.py     # 结构分解
```
需要上一级目录的 `roster_sim.py`；纯 numpy。
