# T20 汇总（第五批正式实验：测试实例 160 个）

各阶段细节见 `报告/T20_0_冒烟.md`（外壳、(e)、后备上限、运行情况）与 `报告/T20_1_下界.md`（下界）。本报告记全部作业跑完后的汇总口径、备查数据与异常。论文的表与图由 `code/t20_paper_tables.py` 从 results/T20 生成。

## 1. 设定
- 机器：Intel Core i7-10700KF（8 核 16 线程，16 MB L3），125 GB 内存，Ubuntu 22.04.3。
- 软件：g++ 11.4.0（`-O2 -std=c++17`）；Python 3.10.22；LP 用 HiGHS 1.15.1。每个进程 1 个 BLAS 线程。
- 并行：正式作业 12 个并行，T20-1 的 LP 9 个并行。
- 预算：m = 2、3、4 是 300 秒，m = 6 是 600 秒，m = 8、10 是 1800 秒，m = 15、20 是 3600 秒。本方法一类的预处理用时从预算里扣。
- 作业：q2–q6 共 6120 个（论文表格用的集合，含 (e) 重跑的替换），全部有结果。
  - 搜索型方法的可行解，作业内 judge 重判逐字段一致。
  - 下界 LB = ⌈max_H LP_fr^Rw(H)⌉。m = 20 的下界在 4·S_max 时仍略有上升（中位数 +0.38%），论文如实写一句。
- (e) 的使用（装上 (e) 与后备上限后，按 11-09 的规则）：
  - q6 重跑 274 个 D5-EA：(e) 实际触发 255 个，找到可行解 35 个；没触发的 19 个新旧结果相同，用旧结果。
  - RK-EA 由 (e) 找到解的 27 个，judge 重判都一致。

## 2. 超出预算的最后一代：(a) 主口径、(b) 备查（用户 11-14 定）
- 搜索只在每代开始前检查预算，到点前开始的那一代会跑完。主口径 (a) 用最终解。论文写"每代开始前检查预算、最后一代跑完"，并报超出的最大值：

- (b) = 只认预算到点前得到的解。数据在 `results/T20/strict_budget.jsonl`（`code/t20_strict_budget.py` 生成），每个作业一行，字段 `method`、`inst`、`seed`、`R_b`，另加 `R_a`（(a) 口径）和 `src`（取法说明）。
  - 搜索型：`traj` 每条是完整判定通过后记下的 [资源数, 代, 评价数, 秒, 状态]。R_b 取秒数 ≤ rost5 限时的最后一个可行解；限时对手 = 预算，本方法一类 = 预算 − 预处理。
  - 没有 `traj` 的（PB、GPHH、接入构造、RH-MIP）：方法用时 ≤ 预算 + 1 秒时 R_b = R_a，否则 null。
  - shorteval：240 个在到点时的有限时域解都等于最终的有限时域解，R_b = R_a（搜索后的长期判定与补救两种口径都不计入预算）。
  - T21 的 pbnoconn 跑完后重新生成这个文件，见第 5 节。

- 备查表：`python3 code/t20_paper_tables.py . --strict` → `results/T20/tables_strict_budget.tex`。
  - 该脚本加 `--strict` 时原来也会把图写进 manuscript/figures/，11-14 改成 `--strict` 时不存图，论文文件没有改动。
  - (a) 的表格行在临时目录重算一遍，与论文里现有的完全相同。
- **(a)(b) 两套的对比结论相同。**
  - 下界、消融、窗口扫描、shorteval 统计几张表逐行相同。
  - 平均秩：本方法两套都是 1.08，排第一；对手的平均秩变化在 0.3 以内（RH-MIP 5.40 → 5.68，其余略降）。
  - 配对比较：本方法的平均差距两套逐格相同；胜 / 平 / 负只在 D5-EA（m = 15：3 → 2 个可比实例）和 RH-MIP 上变，都是可比实例变少，没有新的"负"。
    - 对手的超出差距：ES、RK-EA、RDD-hand 最多差 0.1 个百分点，D5-EA 最多差 0.3；RH-MIP 可比实例变少，变化大些（例如 m = 2 时 20 → 14 个实例，+12.0 → +10.7；m = 10 时 18 → 15 个，+17.2 → +12.6）。
  - 本方法有"负"的只有对 ES 的三格，两套一样：m = 3 是 16 胜 / 2 平 / 2 负，m = 4 是 16 / 1 / 3，m = 6 是 17 / 0 / 3。
  - Holm 校正后的 p 值两套都小于 1e-12（最大的是 D5-EA：(a) 7.7e-14，(b) 1.1e-13）。
  - 求解率只有两行变：RH-MIP（m = 2、3、8、10、15、20 依次从 100、100、100、90、65、70 降到 70、90、95、75、45、55），D5-EA 的 m = 15 从 11 降到 6。

## 3. 长期可行的依据（11-14 审核第 3 点）
- 按最终解的 judge 重判计数，`code/t20_cert_counts.py` 生成 `results/T20/cert_counts.md`。
- **判出循环**：`verify_cert` = 1 且 `exact` = 1，即 60 万格复核中判出循环，且循环经精确核对，是严格证明。等于作业记录的 `proven` 字段。
- **只有 60 万格复核**：可行，但不满足上一条，即复核 60 万格 0 缺岗、没判出循环。
- 字段来源：
  - 搜索型方法用作业内 judge 重判的结果 `judge`（`check_judge` = 1，与搜索时的记录逐字段相同，包括 `verify_cert`、`verify_period`、`exact`）；
  - shorteval 的最终解本身就是搜索后按长期口径 judge（或 judge + rescue）的结果，取作业记录；
  - 确定性方法（PB、GPHH、接入构造、RH-MIP）没有单独重判，取定台数输出的同名字段（size 的判定与 judge 是同一段代码）。

## 4. 与别的项目共用机器的作业（11-11 起；用户定不重跑）
- 时间段：从别的项目的输出文件时间推出来，三段连起来是 **11-11 13:33 到 11-13 22:25**：
  - `~/lbbd_probe`：11-11 13:33 起自检与前几步，14:07–19:25 跑 lbbd_run.py；
  - `~/supermod_probe`：11-11 15:33 到 11-12 15:29；

  - 11-11 14:07–15:56 没有限制，q5 每个作业只拿到 79–84% 的 CPU；
