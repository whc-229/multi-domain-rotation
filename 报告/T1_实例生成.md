# T1 实例生成与训练 / 测试划分（2026-10-27）

## 设定
见 `bench/README.md`。要点：SIX 机型，每站 2–3 种，δ_s ∈ {0, 1, 2, 4} h，共享工具池；m ∈ {2, 3, 4, 6, 8, 10, 15, 20}；族 K1、K12；
每个 (m, 族) 训练 6 个（序号 0–5）、测试 10 个（序号 6–15），共 256 个。种子由 (m, 族, 序号) 的 md5 决定。

## 命令
```
python3 code/gen_mdrr.py                                   # 生成，约 5 秒
MDRR_BENCH=<临时目录> python3 code/gen_mdrr.py              # 重跑到别处，再比较 md5
python3 code/t1_check.py                                   # 逐项核对 + 仿真核对，约 7 分钟
```

## 异常与改动
- **K_s ≥ 2 的仿真**：C++ 文本格式本来就有每站 K 一列，rost4 也读入了，但 rost4 和 Python `certsim` 的仿真里每站只有一个"下次空闲时刻"，实际只支持 K_s = 1。所以本任务的仿真核对只做 K1 族；K12 族要等 T3 的 rost5。
  rost5 的做法（技术选择）：把站 s 拆成 K_s 个岗位，每个岗位是一条首尾相接的班链。"每格恰好 K_s 台在岗"与"K_s 条班链各自连续覆盖"等价（每格开始的班数等于结束的班数，班可以两两接上）。LP（`tool_lb`、`freshlb`）本来就按 K_s 写覆盖约束，不用改。
- 实例名不再用 `make()` 的 `m{m}-n6-s{seed}`，改为 `m{m:02d}-{族}-{序号:02d}`；JSON 里另存种子。
- `code/mdrr.py`：公共导入（把 prior 的 `多型号多地/` 加入路径）、实例读写、`load_train()` 只允许按名字加载训练实例。
- `code/cpp/mdrr_inst.h`：从 rost4 抽出的实例读入代码，供 `inst_dump` 使用。（更正：rost5 没有用它，而是在 rost4 的 `Inst` 结构上直接加了 `psite` 字段；两份读入代码由 T3 的 rost5 vs rost4 核对间接覆盖。）
