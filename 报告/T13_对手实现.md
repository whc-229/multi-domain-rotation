# T13 对手的实现、核对与冒烟测试（2026-11-04）

只用训练实例。8 个对手和我们的方法都在 rost5 上实现，共用同一个外壳。冒烟测试 40 个作业在 11-03 跑完（11-04 写报告）。

## 结论先看
- **核对通过。** 8 个对手各 20 组（实例, 基因型或参数），C++ 与 Python 参考实现逐字段一致，160 / 160。
- **冒烟测试：40 个作业里 36 个出了长期可行解。** 4 个没有：
  - **d5，m04-K1-00 与 m04-K12-00**：没开始搜索就失败，原因在实现上，见第 4 节。
    - 起点（全 0 基因）的定台数，在 m04-K1-00 上 4 个起点都没定出台数（冒烟时机器满载用了 629 秒，空闲时复现用了 253 秒）；在 m04-K12-00 上 25 分钟没结束，被调度器结束。
    - 两个原因：d5 的默认排序本身偏弱；回溯修复让缺岗多的台数下一次评价比随机键（rk）慢约 100 倍，定台数又要反复评价这种台数。
  - **FIFO，m04-K12-00**：定台数的 4 个起点上都定不出台数（约 1 秒失败）。
  - **PB，m04-K12-00**：定出 85 个资源，但 60 万格复核有 2 次缺岗，不可行。
  - 这两个都不是规则本身不可行：给足资源（PB 1.5 倍、FIFO 2 倍）时 60 万格内 0 缺岗。失败出在共用的定台数过程，见 4.2。
- **RH-MIP 在冒烟设置（每步 120 秒）下等于"PB + 计划"。**
  - 4 个实例上，第 0 步（定机队的那一步）都在限时内没有改进热启动解（PB 的排班），机队就是 PB 的台数。
  - 之后各步都很快解到最优、目标为 0（不加台）。
  - 在 m04-K12-00 上，RH-MIP 的计划让 PB 变得可行（84 个资源，PB 本身 85 个也不可行）。
- d5 即使出了解也很差：搜索每秒只跑约 1–4 代（其他搜索型方法每秒 100–1000 代），m02-K1-00 上比 FIFO 还多 1 个资源。

## 2. 各对手的做法与原文献 / 原代码的差别

| 编号 | 做法（本实现） | 与原文献或原代码的差别 |
|---|---|---|
| FIFO | 可用、允许的机器人里就绪最早的；工具按保养时长；不提前大修。权重 w = [1, 0, 0, 0, 0, 0, 1, 0] | 无 |
| PB | 相位平衡，T8 的手写规则（w = [0.1, 0, 10, 1, 0, 0, 1, 0.1]）；不提前大修 | 无 |
| ES-DW | 逐实例 ES 调 8 维派工权重（curdef），定台数下降评价；不提前大修 | 试点的 curdef，评价方式从"给定台数缺岗"改成与其他方法相同的定台数下降 |
| ES-LP | ES 调 14 维权重，w13 是 LP 引导项（lpz）；启动窗口内按 LP_fr^Rw 的提前大修计划（planf，严格窗口） | 试点的 lpgplan；LP 引导文件和计划换成启动窗口内的 LP_fr^Rw（`results/T13/rules/*.lpgw.txt`） |
| GPHH | GP 树打分，打分小的先派；工具按保养时长；直接定台数，不逐实例搜索 | 规则由 T14 训练；算子、特征与试点相同 |

| RDD-hand | 上一篇的 RDD：默认规则 PB，备选表与 T7 相同（含"本班后提前大修"，只在窗口内），ρ = 0.1、q_on = 0.4 | 不含 LP 的任何信息 |
| RH-MIP | 滚动时域整数规划，见下 | 文献里的 RH-MIP 多是有限时域；这里滚到 4·S_max 后按 PB，再按共用外壳定台数与判定 |

**RH-MIP 的技术选择**（`code/t13_rhmip.py`）：
- 每一步：起点 ff = j·Δ，时域 [ff, ff + L_w)。
  1. 用 Python 参考仿真（与 rost5 逐位一致）按已提交的计划 + PB 推进到 ff，取此刻的真实状态。
  2. 窗口模型用 freshlb 的时间展开网络，只建窗口内的节点与弧，全部取整数。
     - 第 0 步的供给是机队变量（代价 1，即定机队）；之后只能加台（代价 1）。
     - 缺岗松弛代价 100，保证模型总有可行解。
     - 提前大修弧只在值岗开始 D < W 时有。
  3. 用"已提交计划 + PB"推进到窗口末端的排班作为热启动解。
  4. HiGHS 单线程、mip_rel_gap = 0、限时求解，把 [ff, ff + Δ) 内开始的值岗提交进计划。
- 滚到 4·S_max 为止，之后按 PB。机队 = 第 0 步的机队加之后的加台。
- 最后用 rost5 size 定台数（起点 = 上面的机队，规则 = 按计划派 + PB 兜底），按共用外壳判定。
- 参数：L_w = S_max，Δ = ⌈S_max / 2⌉（共 8 步），每步限时 = 总限时 / 8。冒烟的总限时 960 秒，每步 120 秒。

RH-MIP 的各步（4 个实例相同的模式）：

### 4.1 D5-EA 的问题
- **回溯修复让评价很慢。** 在缺岗多的台数下，每次缺岗都要回溯 12 个决策重排。m04-K1-00 上的实测（6 万格，不判环）：

  | 台数（机器人 / 工具） | D5 缺岗数 | D5 用时 | RK 缺岗数 | RK 用时 |
  |---|---|---|---|---|
  | [8, 2, 20, 3] / [0, 0, 15, 0] | 80 588 | 4.65 秒 | 80 532 | 0.05 秒 |
  | [10, 2, 25, 4] / [0, 0, 20, 0] | 27 821 | 2.28 秒 | 25 718 | 0.03 秒 |
  | [13, 3, 33, 6] / [0, 0, 26, 0] | 11 | 0.03 秒 | 0 | 0.02 秒 |

  修复并没有减少缺岗（D5 的缺岗还略多，排序不同），用时却多了约 100 倍。定台数的下降过程和搜索的评价都会经过这种台数，所以 m = 2 上搜索每秒只跑 1–4 代。
- **默认排序本身也偏弱，起点定不出台数。**
  - 同一台数 [13, 3, 33, 6] / [0, 0, 26, 0]，D5 的起点 6 万格内有 11 次缺岗、判出带缺岗的环；RK 的起点 0 次。
  - m04-K1-00 在空闲机器上复现：4 个起点（默认台数的 100%–150%）都定不出台数，用时 253 秒，搜索没有开始。
  - 资源给到约 1.5 倍（[20, 5, 50, 9] / [0, 0, 40, 0]）时，D5 的起点有严格证明。所以不是 D5 根本不可行，而是共用的定台数起点对它太小。
- 这一节是按上一篇的 dec5 忠实移植的结果。第五批如果照原样跑，D5-EA 在 m ≥ 4 上大概率没有解；改不改见"待确认"。

### 4.2 FIFO 与 PB 在 m04-K12-00 上没有可行解
- FIFO：4 个起点（默认台数的 100%–150%）都定不出台数。
- PB：定出 85 个。定台数时的判定（6 万格判环，判不出时 24 万格）通过了，但 60 万格复核有 2 次缺岗。
- 把 PB 定出的台数按比例放大，用 `rost5 eval` 跑 60 万格（不是定台数，只看可行性）：

  | 放大倍数 | 资源数 | FIFO 缺岗 | PB 缺岗 |
  |---|---|---|---|
  | 1.0 | 85 | 400 | 2 |
  | 1.5 | 130 | 16 | 0 |
  | 2.0 | 170 | 0 | 0 |
  | 3.0 | 255 | 0 | 0 |

  两个规则在资源足够时都可行（60 万格 0 缺岗、没判出环）。所以失败出在共用的定台数过程：
  - FIFO 需要的资源超出了起点范围（150%）；
  - PB 的下降停在一个短时域可行、长时域不可行的台数上，复核不通过时外壳不会再加台。
- RH-MIP 和 RDD-hand 都以 PB 为底，它们的计划或偏离让结果变得可行。
- 以前的任务里也按同样的外壳处理（例如 T12 的 m06-K12-00 严格窗口规则复核 1 次缺岗，记为不可行），所以这不是这次新出现的口径。

## 5. 技术选择
- RH-MIP 的窗口长度、步长、限时见第 2 节。
  - 冒烟显示每步 120 秒时第 0 步定不出比 PB 更好的机队。第五批我打算把总限时的一半给第 0 步，其余 7 步平分；
    这是技术选择，第五批开跑前在一个 m = 2 实例上试一次再定。
- D5-EA 的修复深度 12 取自上一篇。
- 冒烟里 GPHH 用 PB 近似树，只为确认 tree= 路径能跑通。

## 待确认
- **D5-EA 怎么处理**（影响对手的公平性，所以请定）。三种做法：
  1. 照原样跑，失败就记"没有解"。最忠实，但 D5-EA 在 m ≥ 4 上基本是空的，审稿人可能认为是实现问题。
  2. 起点定台数时关掉修复（同样的排序，不回溯），搜索时保留修复。起点能定出来，搜索仍慢。
  3. 修复只在启动窗口内做（窗口后本来就按默认取第一个），并给起点定台数设限时。
  
  我倾向 2 + 给起点定台数设限时：不改 D5 的搜索本身，只让它能开始。三种都要改 rost5，改完跑一致性核对。
- **共用外壳要不要在失败时补救**（对所有方法一样，但会改变弱规则的结果，所以请定）：
  - 现在：4 个起点都定不出、或复核不通过，就记"没有解"。
  - 可选补救：起点再加 200%、300% 两档；复核不通过时每次加 1 个资源（加在复核第一次缺岗的站对应的机型上）再复核，最多 10 次。
  - 我倾向加补救：FIFO、PB、D5 的失败都是外壳造成的，不补救会让弱对手显得比实际更差，审稿人会追问。补救对我们的方法同样适用。
- 如果仍有作业没有解，第五批怎么进统计：按"没有解"记、排名排在所有有解的方法之后；还是单独列出、不进平均。这是统计口径，请定。
