# T21 规则来源对照（pbnoconn vs noconn）

## 1. 设定
- 目的（TASKS"T21 规则来源对照"，11-14 用户定）：只比较默认规则的来源，即 PB 规则与松弛规则（σ）。两边都不构造启动期，偏离窗口都是 ⌊0.5·S_max⌋。参照是 T20-3 已有的 `noconn`。
- 实例：m ∈ {4, 6, 8, 10} 的 80 个测试实例 × 种子 0–2，共 240 个作业。预算同 T20（m = 4 是 300 秒，m = 6 是 600 秒，m = 8、10 是 1800 秒），12 个并行。
- 实现：`code/t20_job.py` 加方法 `pbnoconn`（函数 `pb_spec`）。走与 noconn 相同的分支（rddfd、偏离窗口、补救外壳与 (e)、后备上限、作业内核对），只换规则选项。
  - **规则选项**：noconn 是 `rlp=<实例>/noconn.rlp planW=2·S_max`，pbnoconn 是 `w=<PB 权重> facloop`。PB 权重与对手 PB、RDD-hand 相同（`W_PB` = 0.1, 0, 10, 1, 0, 0, 1, 0.1）。
    - `facloop` 让线性权重规则也走"放大起点倍数循环"；松弛规则在 rost5 里本来就走这个循环（rost5.cpp 的 `size_rule_hs`）。不加它，PB 的定台数只试一次起点，补救外壳就与 noconn 不同。
    - 起点基数：noconn 用规则文件里的台数（σ 的台数），PB 用实例默认台数。这是规则本身带的，与对手 PB、RDD-hand 相同。
  - **搜索限时**：noconn = 预算 − 预处理用时（σ 规则等在作业外按实例算一次，用时从预算里扣）；pbnoconn 不需要预处理，限时 = 预算。两者的方法总用时上限相同，都是 T20 的预算。
    - noconn 扣掉的预处理在 m = 4、6、8、10 上中位数占预算 0.6%、1.6%、1.5%、1.8%，最大 7.4%。
  - 作业内核对同 noconn：judge 重判最终解、抽样缺岗与 rost5 eval 相同、Python 参考实现重跑最终解（PB 权重按 14 维传入，后 6 维补 0，与 `code/t13_check.py` 相同）。
  - 实际上 pbnoconn 就是对手 RDD-hand 把偏离窗口从 2·S_max 改成 0.5·S_max（另加 resetopt，RDD-hand 也有）。
- 结果写 `results/T20/ours/jobs/pbnoconn__<实例>__s<k>.json`（与 noconn 同目录同格式）。

## 2. 两条命令（开跑前核对，m06-K1-07 种子 1）
命令由 `t20_job.py` 生成，拦下 rost5 调用只取参数，不运行（脚本在 scratchpad，作业内的 `fddump=` 临时文件参数略去）：

```
noconn:   code/cpp/rost5 rddfd bench/instances/test/m06-K1-07.txt 365 60000 600000 1140 1000000000 590.0 4 12 1 0.1 0.4 rlp=results/T20/ours/pre/m06-K1-07/noconn.rlp planW=380 rescue W=95 resetopt stall=30 swap=0.5 fdsel=best
pbnoconn: code/cpp/rost5 rddfd bench/instances/test/m06-K1-07.txt 365 60000 600000 1140 1000000000 600.0 4 12 1 0.1 0.4 w=0.1,0.0,10.0,1.0,0.0,0.0,1.0,0.1 facloop rescue W=95 resetopt stall=30 swap=0.5 fdsel=best
```

- 逐项对照：时域（365 / 60000 / 600000 / T_fit = 6·S_max = 1140）、代数上限、(4 + 12)、种子、ρ = 0.1、0.4、rescue、偏离窗口 W = 95 = ⌊0.5·190⌋、resetopt、stall 30、互换 0.5、fdsel = best 都相同。
- 只有两处不同：
  1. 规则选项（就是要换的默认规则）；
  2. 搜索限时 590.0 与 600.0：noconn 扣了这个实例 10 秒的预处理，见上。

- **冒烟发现并修好一处核对代码的问题**：两个作业记录里的 `check_py` 都是 0。
  - 原因：作业内 Python 核对（`py_check`）调 rost5 eval 时，把规则选项都放在最后一段。rost5 eval 只从第 3 段读权重，选项区的 `w=` 会被**静默忽略**。所以 C++ 那边是按全零权重跑的，m04 报缺岗 67，而 Python 按 PB 权重跑，缺岗 0。
  - 搜索本身不受影响：rddfd 的规则选项解析正常，judge 重判与抽样缺岗都一致。
  - 修正：`py_check` 改用 `t13_job.eval_args` 拆选项。它把 `w=` 的权重放进第 3 段，并去掉只对定台数有用的选项（facloop、rescue 等）。原有方法（ours、窗口扫描、noconn、shorteval）的选项里没有 `w=` 和这些选项，在 5 个实例 × 4 个方法上核对过，生成的 eval 命令与原来逐字相同。已有结果不受影响。
  - 两个冒烟作业的搜索结果用修好的代码离线重做 Python 核对，都一致（见上表）。冒烟记录里的 `check_py` = 0 保留原样，不改。
