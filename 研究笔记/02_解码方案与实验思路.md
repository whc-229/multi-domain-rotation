## 1. 上一篇的 RDD 直接搬过来，有哪些地方不合适

| RDD 原设计（`decoding-research`） | 本问题的情况 | 要怎么改 |
|---|---|---|
| 槽的位置：作用在第 ⌊pN⌋ 个决策，N 为时域内的最大班数 | 时域无限，没有 N | 槽只作用在两个地方：启动窗口 [0, H_dev)，以及一个重复的周期 P |
| 规则：在训练实例上离线学（GP、ES16、LLM），用代理分评价 | 老师的批评是"问题先验" | 默认规则由每个实例的松弛解推导出来；学出来的规则只作对照 |
| 动作：派一台现有机器人，或者新开一台 | 全新机队在 t = 0 一次买定，"新开"等于在相位 0 等到某个时刻再上岗；另外还有提前大修和选工具 | 备选表：规则排序的其他候选机器人（可以跨机型）、"本班后提前大修"、换工具 |
| 一个岗位，一条决策序列 | 多个站点会在同一格交接 | 决策按 (时刻, 站点) 排序，同一格内的站点顺序由规则定 |
| 可行：有限时域内无缺岗 | 必须永远可行 | 窗口之后完全确定、状态有限，于是证书适用 |
| 目标：资源数 + 均衡度，用 HV 评价 | 待定 | 见 §2 |

## 2. 目标：一个还是两个
- 解码方案的丰富程度，主要看基因怎么映射到决策，和目标个数关系不大。单目标下照样可以比较多种解码。
- 但单目标 f1 有个实际问题：f1 是整数，大量基因型的适应度相同（平台），搜索缺少方向。所以单目标时要加一个次级排序，比如缺岗格数。这是技术选择。
- 如果要第二个目标，我推荐"提前大修次数"，不用原来的均衡度：
  1. 冲突是真实的：L1-1 × 3 岗的精确解，不提前大修要 29 台；提前大修 9 次，只要 27 台。
  2. 松弛可以给出**下界前沿**：在全新启动 LP 里加一条约束"提前大修流量 ≤ ε"，对每个 ε 解一次，就得到一条分段线性的下界曲线。理论和多目标正好接上。
  3. 和 RDD 的多目标框架（NSGA-II、HV）一致。
- 原来的均衡度 f2 在无限时域里不好定义：第三项"首次维修时间间隔"只和开局有关；进入周期以后，同型机器人轮流走同一个模式，工作量本来就均衡。
- 提前大修只允许出现在启动窗口内，这样次数是有限的。

## 3. 我们的解码：周期规则偏离解码（暂称 C-RDD）

### 3.1 默认规则由松弛推导（R_LP）
从允许提前大修的全新启动 LP 的解里读出四样东西：
- 机队：各型台数 N_k，由 LP 值取整；
- 派工：在时刻 t、站 s 交接时，优先选"累计派工比 LP 累计流落后最多"的机型；同一机型内，按 LP 的相位分布选机器人；
- 提前大修：按 LP 的提前大修流量，在指定时刻、指定相位让机器人提前大修（即现有的 planf）；
- LP 时域 H 之后：改用稳态 LP 的机型—站点比例。规则从此与时间无关；"落后量"这类特征要截断，保证状态有限（技术细节）。

这里没有训练：每个实例解一次 LP 就得到规则。规则来自松弛，不是手写。

### 3.2 基因型
- **窗口偏离槽**：位置基因映射到启动窗口 [0, H_dev) 内的第 ⌊p·N_dev⌋ 个决策，动作基因从备选表里选一项。和原 RDD 相同，只是 N 换成窗口内的决策数。
- **周期偏离槽**：位置基因映射到周期 P 内的某个 (站点, t mod P)，以后每隔 P 重复一次。
  - 这样偏离也能改变稳态，不只改变开局。
  - 规则加周期偏离仍然是确定性的，状态里多一个 t mod P，证书照样适用。
  - 推测：周期偏离可能让循环更短、更容易判出（10 站时有一半判不出来）。这一点需要验证。
- **机队**：每型 ΔN_k ∈ {−1, 0, +1}（相对 LP 的取整值），或者沿用试点的"补足 / 回删"定台数循环。这是技术选择，先做小试验比较。
- 偏离率 ρ、窗口长度 H_dev、周期 P：只在训练实例上选定。

### 3.3 备选表
- 规则排序的其他可用机器人，可以跨机型；
- 本班值完后提前大修（只在窗口内）；
- 换工具，按规则排序。

### 3.4 解码流程
1. 解 LP，得到规则 R_LP 和初始台数。
2. 按 (时刻, 站点) 的顺序做决策：有激活槽的决策取槽里的备选，没有槽的按规则。
3. 窗口之后只剩规则加周期槽，同时检测状态是否重复。
4. 环内无缺岗，证书成立；否则按缺岗格数罚分。

## 4. 对照：分三层（10-27 晚修订）

用户指出：只比解码，实验重心不清楚，长周期问题本身也没有体现。所以对照改成三层，再加一层参照：

| 层 | 要回答的问题 | 比什么 |
|---|---|---|
| 建模层 | 长周期问题应该怎么建模，才能交给进化算法优化 | 同一个解码、同一个优化器，换不同的时域模型 |
| 表示层 | 在选定的模型下，用什么解码最好 | 8 种解码（§4.2） |
| 算法层 | 优化器要不要为这个问题做适配 | 适配项的消融；换优化器的稳健性检查 |
| 参照 | 离最优还有多远 | 下界前沿、小规模精确解 |

论文的故事线：长周期怎么建模（问题）→ 松弛给出下界（理论）→ 由松弛推导规则，放进解码器（方法）→ 三层实验。

### 4.1 建模层：长周期怎么建模
| 编号 | 模型 | 做法 | 预期的问题 |
|---|---|---|---|
| M-720 | 原问题，有限时域 720 h | 适应度只看 720 h 内的缺岗 | 试点：一半以上的解长期不可行 |
| M-long | 拉长有限时域 | 适应度看 8 个月、1 年、5 年 | 用时随时域线性增长；试点：10 站时仍只有一半有效 |
| M-roll | 滚动时域 | 每 720 h 重排一次，状态继承到下一段；机队取各段最大值 | 每段只看眼前，可能错过启动期整体错峰的机会 |
| M-cyc | 固定周期的循环排班 | 解是周期为 P 的轮转表，首尾衔接；默认相位已经错开 | 表示不了全新启动：直接从全新机队上线会缺岗，要另加启动方案；P 要事先选定 |
| **M-ours** | 启动期 + 稳态周期 + 证书 | 窗口槽管启动期，周期槽管稳态，证书判定永远可行 | — |

- 统一裁判：每个模型得到的解都要先延拓成无限排班，再用同一套判定评价，判定条件是全新启动、证书成立或 60 万格内无缺岗。
- 记录的指标：资源数、提前大修次数、长期有效率、用时，以及时域拉长时用时怎么增长。
- 试点里 finite365、finite3000 和 cert 的对比，就是这一层的雏形（策略编码 + ES）。

### 4.2 表示层：解码
所有解码都包在同一个无限时域外壳里：基因只作用在窗口内和一个周期内，之后用确定性规则，同样用证书判定可行。这样比较才公平。

| 编号 | 解码 | 来源 | 适配方式 |
|---|---|---|---|
| RK | 随机键，每个决策一个基因 | 原排班软件 | 窗口内逐决策，窗口后按一个周期的基因重复 |
| D5 | 上一篇最好的逐决策解码 | RDD 论文的 dec5 | 同上 |
| PW | 派工权重编码，用 ES 调权重 | 本项目试点 | 天然与时域无关 |
| GP | 遗传规划派工树 | 本项目试点 | 天然与时域无关 |
| SE | 周期结构编码（站点分组 + 显式周期构造） | 本项目试点 | 天然周期 |
| RDD-h | 原 RDD + 手写默认规则 | 上一篇 | 只用窗口槽 |
| RDD-L | 原 RDD + 用代理分学出的规则 | 上一篇 | 只用窗口槽；规则只在训练实例上学 |
| **C-RDD** | **本文** | — | LP 规则 + 窗口槽 + 周期槽 |

参照（不当对手）：
- R_LP 本身（不搜索）：衡量松弛给出的先验有多强；
- 下界：R_rate、LP_fr、LP_fr^R，以及双目标时的下界前沿 LB(ε)；
- 小规模的精确解或近精确解。

### 4.3 算法层：优化器要不要适配
优化器本身保持通用（NSGA-II），因为 RDD 是编码，可以配任何优化器，上一篇也这样论证过。和问题相关的适配放在优化器外面的四个地方：
1. 评价：证书判定的代价大，而且每个解不一样。先用短时域筛掉明显不可行的解，再对剩下的做完整判环。
2. 初始化：全部槽关闭的基因型就是 R_LP 的解，初始种群在它附近生成。
3. 变异：窗口槽、周期槽和机队基因分开变异。
4. 约束处理：不可行解按缺岗格数排序，排在所有可行解之后。

实验：
- 逐项去掉这四项适配；
- 把 NSGA-II 换成 MOEA/D、SMS-EMOA，检查结论是否不变。

## 6. 实验分三批

### 第一批：诊断（用来决定场景和规模）
- 生成实例，并在生成时固定训练 / 测试划分。站数取 2、3、4、6、8、10、15、20；用 6 种真实机型；带工具；每站 K_s ∈ {1, 2}（K_s = 2 是否保留看结果）。
- 每个实例算 R_rate、LP_fr、LP_fr^R（用列生成求解），以及稳态、全新启动两种场景下 R_LP 本身的结果。
- 小实例（2–3 站）用时间展开 ILP 求精确或近精确解，把差距拆成"下界松"和"算法差"两部分。
- 读法：
  - 多站上的启动代价（LP_fr − R_rate）够不够大，决定全新启动是否作为主场景；
  - R_LP 离下界多远、LP 在多大规模时还解得动，决定规模范围。

### 第二批：主对比（场景和规模定了以后）
在测试实例上做建模层（§4.1）和表示层（§4.2）的对比。每个实例跑 n 次独立运行，预算相同。统计口径边跑边定。

### 第三批：消融与敏感性
只用训练实例，或测试实例中的一部分。
