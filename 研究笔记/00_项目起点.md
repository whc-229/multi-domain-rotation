## 1. 来由

- 上一篇论文（仓库 `whc-229/decoding-research`）提出"规则偏离解码"（RDD）：构造规则默认决定每一步，基因只编码稀疏的偏离槽。论文已成稿，**本仓库不改动它**。
- 老师对 RDD 的意见（用户转述，2026-10-27）：
  1. RDD 本质是**问题先验**：效果主要来自把好规则放进解码器。
  2. 建议的方向：
     - **轮转周期 + 松弛下界**：从机器人的维修-值岗循环出发，构造松弛，给出资源数下界；
     - 把**规则放进解码器**作为一个点，和"轮转周期松弛下界"合成一篇论文（老师很建议）；
     - EA → LLM → 规则，学一个采样方法或分布（类似 EoH）；
     - RL 学规则（但"还是规则"）。
  3. 写论文要先想好**实验和谁比、和谁消融**。例如训练网络就要和 PPO、actor-critic 等比。
- 问题复杂度：老师说"能自己做多复杂就做多复杂"，不是硬性要求。
- 用户选择的方向：**多域轮转问题**（多站点、多机型的长周期轮转排班）。

## 3. 已有结果（详见原文件）

### 3.1 理论（`prior/排班MOEA_小样例/超长周期_数学/`）
- **速率（流体）下界**：同型、K 个值班点时 N ≥ ⌈K·ā⌉，ā 为维修超周期内的平均间隔。这就是"轮转周期松弛"的最简形式。
- 稳态（允许等待）：
  - 零余量时，能达到下界 ⇔ 上岗时刻集合在 Z_S 上做 K 重平移铺砌（定理 4）；
  - L = 2 的闭式（定理 5）；
  - L ≤ 4 时离下界至多差 1 台（定理 6.5，机证）；
  - 多站共享的摊薄定理：离下界的差与 K 无关，专点分组的差随 K 线性增长（定理 A）。
- 全新启动：启动代价一般随 K **线性**增长（定理 8）；允许提前大修后，多数序列的线性代价消失（机证表）。
- 随机大修时长：超额台数约 ∝ √K（数值）。
- 判断（原笔记）：理论部分偏数学 / 运筹，单独成文适合离散数学或 OR 期刊。

### 3.2 方法试点（`prior/排班MOEA_小样例/多型号多地/`）
- **下界**：流体 LP、整数台数版、机器人 + 工具 LP；**全新启动时间展开 LP**（`freshlb.py`）。
  - 单站 L1/L2/L3 带工具：稳态下界 10/9/10，全新启动下界 13/11/12，**正好等于已知最优**。
  - 多站：进化解对下界的差距从 25–33% 缩到 5–16%（另一半是启动代价，不是算法差）。
- **精确基线**：周期网络 ILP（需预先固定周期，2–3 站已吃力）、全新启动时间展开 ILP。
- **进化派工策略**：派工打分 = 6–8 维特征加权，(μ+λ)-ES 调权重；策略与时域长度无关。也试了 GP 树。
- **无限期证书**：确定性派工出现状态重复 ⇒ 以后永远按此周期重复；环内无缺岗即证明永远可行。
  - 只按 720 h 评估时，2–10 站有一半以上的解长期不可行；改用"严格证书适应度"后 84/84 次线性运行长期有效（79 次严格证明），资源数平均只多约 0.5。
- **周期结构编码**：站点分组 + 每组一种机型 + 按理论显式构造周期排班，组内再用小 ILP 修正；10 站以内有竞争力，10 站 s2 仍比派工 ES 多 2 台。
- **LP 计划 + 进化派工**（启动代价）：
  - 单型多岗位 L1 系列 9 个实例全部达到"允许提前大修"时的精确最优；
  - 多站带工具（2–4 站，36 组配对）：LP 引导派工 + LP 提前大修计划比不提前大修平均少 0.58 个资源（p = 0.009）；
  - 让 EA 自己学"何时提前大修"无效；错峰时机和机型配比都要由 LP 给出。
- C++ 实现：`cpp/rost3.cpp`（仿真 + 判环 + ES），`cpp/rost4.cpp`（加提前大修、LP 计划、LP 引导）；与 Python 版逐项一致。

| LLM 学采样分布、RL 学规则 | ES、GP 调派工权重 | 只作对照；网络规则要和 PPO、A2C / actor-critic 比 |
| 想好和谁比 | 精确 ILP（小规模）、各站独立、简单规则（先到先派、相位平衡）、原随机键 MOEA、派工 ES、结构编码 | 补 RL 对照；评估统一用证书或长时域复核 |

**轮转周期松弛**（下界 + 松弛解）→ **松弛解生成默认规则** → **规则放进解码器，EA 搜偏离**（证书保证长期可行）→ 实验：下界间隙、与精确 / 规则 / 学习方法的对比、消融。
